# Известные проблемы

Проверено 4 августа 2026 года по текущему коду и конфигурации сборки. Здесь перечислены подтверждённые ограничения, а не любые идеи для будущих версий.

## Распространение и безопасность

| Важность | Ограничение | Текущая защита | Что нужно сделать |
| --- | --- | --- | --- |
| Высокая | Сборки для Windows и macOS не подписаны, macOS-сборка не прошла notarization. | GitHub Actions публикует релиз только после успешной матрицы, добавляет предупреждение и SHA-256 для всех файлов. | Подключить Windows signing, Apple Developer ID, notarization и проверку подписи установленного приложения. |
| Средняя | Проверка публичного HTTPS блокирует буквальные private/reserved IP, но не закрепляет адрес после DNS-резолва; остаётся риск DNS rebinding. | Удалённые входы ограничены схемой, списком хостов, размером, потоковой загрузкой и проверкой архивов там, где это применимо. | Проверять фактический адрес при соединении либо использовать dispatcher с DNS/IP policy. |
| Средняя | Надёжность Electron `safeStorage` в Linux зависит от доступного keyring рабочего стола. | Токены не передаются в renderer; сторонний аккаунт отключается, если шифрование недоступно, вместо сохранения plaintext. | Определять слабые backend и описать проверенные конфигурации keyring. |

Контрольные суммы помогают обнаружить повреждение или замену файла только при сравнении с доверенной страницей релиза. Они не подтверждают личность издателя и не заменяют подпись.

## Ограничения продукта

- Каталог CurseForge в официальных сборках отключён: для публичных бинарников не настроены API key и правила распространения. Импорт и экспорт локальных архивов CurseForge работают.
- Долгие операции используют единый отменяемый и журналируемый lifecycle, но прерванная сетевая загрузка не продолжается побайтно после перезапуска.
- Recovery inbox не предлагает общий retry для скрытых или уже использованных входных данных. Для import или export в состоянии `recovery-required` пользователю может понадобиться заново выбрать архив или место сохранения.
- После перезапуска восстановление archive export намеренно останавливается в `recovery-required`. Лаунчер сохраняет внешний файл и приватные staging-артефакты, но не переименовывает и не удаляет их после истечения одноразового разрешения native save dialog; результат нужно проверить вручную.
- Авторизация Microsoft не реализована; поддерживаются офлайн-профили и совместимые сторонние Yggdrasil-провайдеры.
- LAN discovery и UPnP зависят от сети и роутера, поэтому лаунчер не может гарантировать их работу.

## Архитектурный долг

- В части renderer IPC wrappers ещё остались защитные availability checks, хотя `window.api` теперь единственная preload-поверхность. Их можно упростить во время рефакторинга соответствующих features.
- Совместимость XMCL bytebuffer обеспечивается проверяемым postinstall-скриптом. В будущем его нужно заменить upstream-исправлением или управляемым package patch.
- Детерминированные renderer-проверки и визуальные эталоны запускаются только в macOS Chromium; они не подтверждают поведение native dialogs, window manager и graphics driver на других платформах.
- Реальная установка Minecraft, настоящие роутеры, установленное автообновление, подпись и notarization требуют ручной проверки на целевых ОС.

## Что не является ошибкой

- Предупреждение о неизвестном разработчике ожидаемо для неподписанных сборок Windows и macOS.
- `npm run verify` не упаковывает приложение и не запускает visual/full-install тесты; полный состав проверок описан в [документе о тестировании](testing.md).

Очередность работ зафиксирована в [роадмапе](roadmap.md). Обычные регрессии отправляйте в [GitHub Issues](https://github.com/malyarq/fmcl/issues/new), уязвимости — по правилам из [SECURITY.md](../../SECURITY.md).
